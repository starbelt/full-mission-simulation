# ICM-40609-D IMU simulation (`src/pocketadcs_sim/sensors/icm40609d.py`)

Hardware-faithful simulation of the TDK ICM-40609-D three-axis gyroscope
and three-axis accelerometer, as a bounded, isolated module. It does not
modify the ideal sensor models, `hardware_models.py`, `vemd8080_array.py`,
`examples/hil_stream.py`, or the `esp32/` firmware tree.

## Scope and interface

`ICM40609DModel` exposes exactly three sample paths:

- `process_gyro(omega_body_rad_s)` — 16-bit-quantized gyro readings in
  rad/s for an explicitly supplied body-frame angular velocity.
- `process_specific_force(f_body_m_s2)` — 16-bit-quantized specific force
  readings in m/s² for an explicitly supplied body-frame specific force.
- `measure_gyro(truth)` — gyro readings sampled from
  `truth.angular_velocity_body_rad_s` at `sample_rate_hz` (nearest
  truth-sample interpolation, same helper as the other sensor models).

**Deliberately missing:** there is no `measure(truth)` and no
accelerometer truth path. The `TruthEnvironmentHistory` dataclass carries
no specific-force quantity, so sampling an accelerometer from truth would
require inventing a physical state. Specific force must be supplied
explicitly (e.g. from a dynamics/forces model that computes it).

## Signal chain

Per axis (bias → noise → quantize → clip):

- Gyro: `dps = omega_dps + bias_dps + flicker_dps + N(0, sigma_dps)`;
  `counts = clip(round(dps * 32768 / FSR_dps), -32768, 32767)`;
  reading = `counts * (FSR_dps / 32768) * π/180` rad/s.
- Accel: `f_g = (f + bias + flicker + N(0, sigma)) / g0` with
  `g0 = 9.80665 m/s²`; `counts = clip(round(f_g * 32768 / FSR_g), -32768,
  32767)`; reading = `counts * (FSR_g / 32768) * g0` m/s².

### Noise density, not per-sample sigma

White noise is specified as a **density** in the datasheet's own units and
the per-sample sigma is derived:

```
sigma = density * sqrt(ENBW)
```

Halving the output rate halves ENBW and therefore reduces the per-sample
sigma by exactly `1/sqrt(2)` at a fixed density. An earlier revision used a
rate-independent sigma, which overstated noise at low rates and understated
it at high ones.

ENBW defaults to `sample_rate_hz / 2` (engineering assumption — the
datasheet's 0–10 Hz / 0–100 Hz characterization bandwidths describe the
test setup, not the part). Pass `noise_bandwidth_hz` to pin it.

Datasheet densities: gyro **4.5 mdps/√Hz**, accel **100 µg/√Hz**
(= `100e-6 * 9.80665` m/s²/√Hz).

### Bias instability

`bias_dps` is now three terms, not one constant:

1. the user constant (`gyro_bias_dps`),
2. a **turn-on-to-turn-on** spread — one draw per model instance, constant
   within a run, different across runs,
3. a slowly-varying **flicker** term: a first-order AR(1) Gauss-Markov
   process, the standard engineering stand-in for the 1/f^0.5 corner.

Datasheet magnitudes: gyro **2 deg/s** band, accel **0.25 mg**. The AR(1)
correlation time (**60 s**) is an engineering assumption — the datasheet
gives the magnitude but not the spectrum that would fix it.

All three default to zero, so `ICM40609DModel()` remains bit-exact
deterministic and every datasheet value is opt-in.

Specific force is reported as the sensor output quantity; no gravity term
is added, removed, or implied anywhere in this module.

Quantization is round-to-nearest (ties to even, `np.rint`) onto a signed
16-bit grid of 32768 counts per full-scale unit; clipping saturates at
-32768 … 32767 counts (asymmetric by one count, hence positive saturation
is `FSR * 32767/32768`, not exactly FSR).

## Verified vs. assumed spec values

**Verified (TDK DS-000330 v1.2,
https://product.tdk.com/system/files/dam/doc/product/sensor/mortion-inertial/imu/data_sheet/ds-000330_icm-40609-d_v1.2.pdf,
cross-checked per the task's sensitivity-table notes):**

- Gyro FSR option ±2000 dps (listed sensitivity 16.4 LSB/dps).
- Gyro FSR option ±15.625 dps (listed sensitivity 2097.2 LSB/dps).
- 16-bit data output on the MEMS interface.

**Unverified — marked, not asserted:** the complete FSR option lists for
gyro and accel, the ODR range, ARW/angle random walk, bias-stability and
noise-density figures from the datasheet's tables were not exhaustively
re-verified in this session. The model therefore exposes FSR and sample
rate as constructor parameters instead of hard-coding a full option
table.

**Engineering assumptions (labeled, defaults):**

- Quantization grid = 32768/FSR counts per full-scale unit. Note this is a
  derived choice, *distinct from* the listed sensitivities: 32768/2000 =
  16.384 (not 16.4) and 32768/15.625 = 2097.152 (not 2097.2) counts/unit.
  The listed datasheet sensitivities are rounded/typical values and are
  deliberately NOT used as the model's conversion factor.
- Default gyro FSR ±2000 dps (verified option).
- Default accelerometer FSR ±4 g (a common ICM-40609-D option; treated as
  the default configuration for this sim, not asserted as the device's
  factory default).
- Default sample rate 100 Hz (simulation choice; device ODR not modeled).
- Bias: user constant + turn-on-to-turn-on spread + AR(1) flicker, all
  default 0. Noise: white Gaussian, default 0 (exact zero-noise
  deterministic mode). Density and bandwidth are constructor parameters;
  the datasheet figures are module constants, opt-in.
- Determinism: with an integer `seed`, one RNG stream per sensor is spawned
  from a `SeedSequence` and advanced across calls (never re-seeded), so
  repeated calls with the same input return identical outputs *and* a
  chunked call reproduces a batched one exactly. The gyro and accel use
  separate streams so the call pattern of one cannot shift the other's
  noise realization. With `seed=None`, NumPy draws fresh entropy.

**Datasheet (per task specification, not re-verified against the PDF in
this session):** gyro noise density 4.5 mdps/√Hz; accel noise density
100 µg/√Hz; gyro bias instability 2 deg/s; accel bias instability 0.25 mg.

**Engineering assumptions (labeled, defaults):** ENBW = fs/2; AR(1)
correlation time 60 s.

## Units

- Gyro output: rad/s (body frame), input rad/s.
- Accelerometer output: specific force m/s² (body frame), input m/s².
  The g↔m/s² bridge uses the exact standard gravity 9.80665 m/s².
- Readings are bounded by the configured FSR: negative saturation is
  `-32768` counts (`-FSR`) and positive saturation is `32767` counts
  (`FSR × 32767/32768`).

## Tests

`tests/test_icm40609d.py` covers: conversion round-trips within half an
LSB; per-LSB quantization step; FSR configuration on both gyro options and
accel FSR; asymmetric 16-bit clipping; bias application; seeded
determinism; noise RMS ≈ config; zero-noise exactness; sample-rate
validation; malformed input/config rejection; and a gyro truth-integration
test against a short Basilisk truth run.
